# ADR-0029：开源版无登录模式（拆除人机登录）

- 状态：**已批准（维护者 2026-10-28 拍板）·已实施**
- 日期：2026-10-28
- 决策者：项目维护者
- 影响面：门户/管理台前端（login/accounts/auth-callback 页、site-gate/admin-gate）、服务层登录接线（站点闸、登录闭环端点、首启种子、登录审计消费）、编排与部署（compose 三服务两卷、nginx 分流、.env.example/Dockerfile.prod）、文档与测试
- 前置阅读：`ADR-0028-Valkey替换.md`（同日分叉决策先例）；主仓 `docs/adr/0010/0015/0016/0018/0027`（登录体系沿革，不在本仓）

---

## 1. 背景

开源 fork 此前继承了两代人机登录体系：外源统一登录（OIDC IdP 三容器）与其后的登录
本地化（本地账号表＋bcrypt＋自签 JWT）。两套体系带来了：

1. **开箱即用性差**：起栈前必须配置登录凭证（.env 多个必填键），打开门户先撞登录墙，
   演示/评估的第一步就是配账号；
2. **编排面负担**：参考栈 9 个容器里有 3 个服务于登录（IdP＋其数据库＋一次性种子
   容器），健康探针、nginx 同源分流、审计拉取线程均为它配套；
3. **与产品主线无关**：本平台的主线是「数据表发布为受治理的查询 API」，调用方鉴权
   由 **AppKey 凭证体系**（网关 key-auth＋服务层授权矩阵＋限流＋审计）承担，人机
   登录不是产品能力的一部分。

维护者于 2026-10-28 拍板：开源版彻底去登录，**打开门户就是首页，管理台直接可用，
无任何人机登录/账号概念**——开箱即用演示优先。这是开源 fork 的分叉决策，主仓产品线
不受影响。

## 2. 决策

**开源版拆除全部人机登录；AppKey 机器凭证鉴权原样保留。**

实施口径（本 ADR 对应施工批）：

- **前端**：删除 `portal/login.html`、账号管理页（`admin/accounts.*` 及构建拷贝）、
  OAuth 回调页（`admin/auth-callback.html`）；`site-gate.js`/`admin-gate.js` 替换为
  **无登录模式空壳**（保留文件名与加载位——各壳页有 script 引用与构建期加载序门禁，
  避免逐页删标签；内容为注释＋空 IIFE，不做任何拦截/跳转）；侧栏账号管理项与
  「仅管理员可见」解锁逻辑一并移除；`my.html` 保留（其数据来源是 AppKey 凭证与
  traceId 反查，与登录无关）。
- **后端**：站点闸中间件（整站登录墙）、native 首启种子、登录闭环端点挂载
  （/v1/admin/auth/*）、Casdoor 登录审计消费线程、账号管理代理挂载
  （/v1/admin/accounts/*）全部摘除；`auth_oidc.py`/`auth_native.py`/
  `admin_accounts.py`/`audit_casdoor_puller.py`/`users.yaml` **文件保留不删**
  （v0.1.1 再清尸体），且无任何运行路径触发登录行为；admin 写闸内的
  require_login/角色裁决挂点保留为休眠骨架（off 态恒放行）。
- **编排/部署**：compose 删统一登录三服务＋两卷（参考栈 9→6：etcd/apisix/redis/
  service/batch-worker/portal），service 的登录相关 env 注入全清；nginx 删登录流
  分流段；`.env.example` 删 AUTH_PROVIDER/ONESERVE_AUTH_SECRET/ONESERVE_SEED_ADMIN_*/
  OIDC/统一登录凭证全部键；监控与探活（healthz/monitor）的登录容器探针退役。
- **不动的**：数据面 `/v1/query/*`、`/v1/tags/query`、`/v1/batch/*`、`/proxy/*` 的
  AppKey 鉴权（网关 key-auth＋授权矩阵＋限流）；`/v1/admin/*` 凭证管理端点及其
  管理令牌占位逻辑（dev_token：未配置＝开发占位态）；审计/计量/批量等全部产品功能。

## 3. 备选方案与未采纳理由

| 备选 | 未采纳理由 |
|---|---|
| **保留登录本地化（native 双模）作为缺省** | 仍需首启种子与账号概念，演示第一 步仍是「拿账号」；登录墙代码与页面的维护成本继续挂在开源包上。 |
| **登录默认 off、代码全保留（开关切换）** | 「能一键打开的墙」意味着登录链路（页面/端点/探针/凭证键）必须随包分发并保持可运行，与彻底去登录的目标矛盾；且半尸状态最易腐烂。 |
| **用极简固定口令页代替完整登录** | 引入「看起来像安全」的假象：单口令无账号/审计/锁定语义，比明示「无登录＋网络边界防护」更误导部署方。 |
| **只删编排不删代码（不起即无害）** | 页面与端点仍在产物里，grep/走查/安全审视都会撞到登录残留；验收口径（login/casdoor 归零）无法成立。 |

## 4. 影响

1. **信任边界前移**：管理台公开可访意味着原由登录墙承担的「谁能进管理面」改由
   **部署侧网络边界**承担（内网/安全组/前置反代）。公网部署必须自加访问控制，
   `SECURITY.md` 与 README 已同步该口径。数据面不受影响（AppKey 鉴权仍在）。
2. **参考栈收口 6 容器**： quicker 起栈、更少凭证必填项（.env 仅剩 APISIX_ADMIN_KEY
   一件必改键＋元数据库六变量按需）；健康探针与监控容器清单同步缩减。
3. **模块尸体登记**：登录相关后端文件保留至 v0.1.1 清理（含 users.yaml、错误码中
   auth_required/role_forbidden 的休眠文案）；期间验收 grep 以「login/casdoor 归零、
   尸体文件白名单在案」为口径。
4. **测试口径**：登录页/站点闸/登录闭环用例删除或改锚为「空壳无拦截」反断言；
   AppKey 鉴权与授权矩阵用例全部保留（产品功能）。
5. **回插路径**：如未来需要人机登录（如企业自用部署），回 git 史取回实现；本 ADR
   与各文件的碑注注明历史形态位置，不做任何「低成本开关」承诺。

## 5. 回退方案

本决策为分叉方向而非可开关配置，**不提供运行期回退开关**。如需恢复登录：

- 以本 ADR 实施前的 git 提交为参考形态，回放登录页面/端点/编排的接线（各摘除点
  均留有碑注：main.py 登录接线、compose 统一登录三服务、nginx 登录分流、
  site-gate/admin-gate 实体实现）；
- 恢复后须同步回 `.env.example` 登录凭证键与 healthz/monitor 探针行，并重建
  portal 产物（`python3 scripts/build_portal.py`）。

## 6. 验收（可执行）

```bash
# 1) 门户产物重建且登录页归零
git ls-files | grep -c 'login.html'          # 期望 0
python3 scripts/build_portal.py              # 全绿（含加载序门禁）

# 2) 编排语法与服务数
docker compose config -q                     # exit 0
docker compose config --services | sort      # 期望恰好 6 个服务

# 3) 验收 grep（testkit/ 除外应接近零，保留项＝尸体文件与碑注）
grep -rli 'casdoor' --include='*' . | grep -v testkit | sort
grep -rc 'AppKey\|appkey' -r service/ | awk -F: '{s+=$2} END {print s}'   # 仍大量存在

# 4) 全量测试（CI 同口径）
python3 -m pytest tests/ -q -rs               # 全绿

# 5) 冒烟：起服后门户数据端点 200
REDIS_URL=redis://localhost:6379/0 uvicorn app.main:app --port 8001 &
curl -s localhost:8001/v1/portal/catalog | head -c 200
```
