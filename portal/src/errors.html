错误响应长什么样

平台所有失败响应统一为同一个信封（字段名向后兼容：error／message 不改名）：

{"error": "invalid_key", "message": "键格式不合法", "param": "key",
  "traceId": "8f1c…", "request_log_url": "my.html?trace_id=8f1c…",
  "docs_url": "errors.html#invalid_key"}
  • error：机读错误码，与下表一一对应。
  • message：人话说明，可直接展示给你方用户。
  • param：哪个参数出错——照着改就行（仅适用时出现）。
  • traceId：本次调用的追踪号；抱怨问题时附上它即可精确定位。
  • request_log_url：点开就能看到这次调用（含被网关拦下的）。
  • docs_url：本页该码的锚点（即你正在看的下表）。

码段规则：系统级 vs 服务级

下表全部机读码分两段——看「来源」与「HTTP」两列即可分辨自己遇到的是哪段：

系统级（HTTP 面码）
请求没走到业务逻辑就被挡下或失败：网关码（来源列＝网关，如 auth_failed 401——没带 apikey 头或凭证无效）与服务层 HTTP 面码（HTTP 列非 200，如 invalid_key 400、rate_limited 429）。特征＝HTTP 状态非 200，响应信封 error 字段就是错误码，照「解决方案」列处理。
服务级（结果行／任务级码）
请求本身成功（HTTP 200），是查询结果里单个键或单个任务出了状况：kv_read_failed（结果行）逐键看行内 error 字段；kv_unavailable、job_state_inconsistent（任务级）在批量任务记录里看。本表 HTTP 列显示「—」的即这一段（行内标注「结果行／任务级机读码，非 HTTP 信封」）。

对号入座：凭证/授权类（401/403）→ AppKey 发放页领/重签凭证（授权开通找平台运营组）；限流/配额类（429）→ 查看配额。也可用上方「网关／服务层」筛选只看一段。
