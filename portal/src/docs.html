快速接入（四步）

从零到接入生产的主路径，每步都可点
  1. 第 1 步 · 申请授权

    联系平台运营组申请授权，流程与时效以平台运营组为准；申请接入页 →

  2. 第 2 步 · 领取凭证（AppKey）

    到AppKey 发放页自助领一把沙箱凭证（sb_ 开头）先调通；正式凭证另行审批发放

  3. 第 3 步 · 在线调试

    在接口调试台选已发布服务、粘上凭证发一次真实调用，验证链路与数据

  4. 第 4 步 · 接入生产

    到服务目录选定服务，按其 API 详情页的入参出参表与报文示例，在你的业务系统里直连网关接入

第 1 步是正式接入主路径；第 2 步沙箱凭证用于先行调试。分步操作细节见下方「5 分钟上手」。

术语表（一句话版）

默认收起，要用时展开
展开术语表（7 条：网关／AppKey 与 secret／查询键／上游供数口径／字段级授权／降级／演示数据）
网关
所有请求进平台的「大门」：先验身份，再决定放不放行、转给哪个服务。它不存业务数据，只负责把关和转发。
AppKey 与 secret
AppKey 是你的调用方身份标识，随请求头 apikey 携带。secret 是签发时只显示一次的配套密钥，平台只存它的摘要；当前它不参与请求签名——这条如实写明，避免按旧印象误配。secret 请自己收好，平台找不回。
查询键
平台用 K/V 视角看数据：给一个键，返回它的标签值。键的生成方式（摘要、编号、UUID…）是上游供数侧的事，平台不关注键的加密算法；键的格式要求由每个服务的注册声明（入参 pattern）给出，默认宽松、按服务而定。
上游供数口径
键值怎么算、怎么规范化，属于上游 ETL／数仓导出侧与调用方之间的约定；平台只按服务注册声明的模式验收，不做加密语义判断。同一份数据口径不一致会导致查询静默查不到——所以约定由供数侧与消费方对齐。
字段级授权
授权可以细到「哪个字段」。平台按授权白名单做投影：没批给你的字段，经任何接口都零出现——不是前端藏起来，是后端根本不返回。每个服务实际开放的字段以其详情页出参表为准（原字段字典页已随 297 宽表字典体系下线，表级 schema 元数据就位后重建）。
降级
出故障时的「退而求其次」：存储不可用时平台拒绝服务（返回 503），而不是读脏数据；页面侧的兜底只有带角标的演示数据（见下条），不冒充真数。降级不等于静默假装成功。
演示数据
真实端点不可达时用来维持页面可看的样例数据，一律带「演示数据」角标，接口返回里也标明来源。带角标的数不是真数，不能当结论用。
错误码中心可一次查到全部机读错误码与解决方案（网关＋服务层同源）；每个服务的错误码与出参也可在其 API 详情页查看，例如用户标签域 · KV 点查。接口报错时可把响应里的 traceId 拿到我的接入反查整个调用过程。

5 分钟上手（三步）

每步都可点，点进去就是真实页面
  1. 第 1 步 · 拿一把凭证（AppKey）

    到AppKey 发放页领一把沙箱凭证（测试用，正式凭证另行审批；sb_ 开头，7 天免费）。没有 OA 批件也能先领来用。领到凭证后下一步：去接口调试发一次查询 →

  2. 第 2 步 · 发一次查询

    打开接口调试台：选一个已发布服务、把沙箱凭证粘进 AppKey 输入框，key 用预填的示例值（可改）点「调用」（curl 样例自动带 apikey 请求头，可一键复制）。查询键由上游供数侧生成，平台全程无手机号明文。调通后下一步：去审计查询看这次调用留下的记录 →

  3. 第 3 步 · 看这次调用留下的记录

    到审计查询按追踪号（X-Trace-Id）或调用方检索；只看自己的调用就进我的接入（凭证／配额／调用记录）。想再练一轮？回第 1 步再领一把凭证 →

三步都指向真实页面与真实端点（POST /v1/svc/usr-basic-info 经网关，请求头 apikey 携带凭证）；本页不放任何演示用假链接。

限流与配额

平台按调用方（AppKey）× 路由维度限流；限额就是「我的接入」页「我的配额」卡里登记的日限额（quota_daily）与速率（quota_qps）——页面看到的数值与网关拦截的数值是同一个来源，不存在两套口径。

被限流拒绝时返回 HTTP 429，响应头带机读原因 X-RateLimit-Reason，取值三档：

global
撞当日配额（quota_daily）：跨路由累计，到东八区次日 0 点重置。
endpoint
撞该路由的速率上限（quota_qps，按 route×consumer 计），短时窗口恢复。
concurrent
撞并发上限（同一调用方同时进行的请求数），请求完成即释放。

配额头随响应返回，便于自检余量：速率档 X-Endpoint-RateLimit-Limit / -Remaining / -Reset，日配额档 X-Global-RateLimit-Limit / -Remaining / -Reset。未登记配额的凭证不上限流（如实不限）；需要调整额度请联系平台运营调整登记配额。

  • 已强制生效的限流（批量通道）

    批量任务通道：单任务 ≤ 100 万键、每租户并发 ≤ 1、每租户日 ≤ 500 万键；超限返 429，并带 X-RateLimit-Reason（concurrency／per_job／daily）。

  • 凭证发放限频（生效）

    自助发放限频：同租户 5 次/小时、同 IP 10 次/小时，超限返 429。

口径依据：configs/apisix/init_routes.py（网关路由）／service/app/batch.py（批量配额）／service/app/appkeys.py（发放限频）／service/app/ratelimit.py 与 my_access.py（登记配额＝拦截值同源）。

找谁

  • 接入口径咨询（字段、流程、凭证）

    联系平台运营组；OA 系统地址与申请模板同渠道提供（真实电话/邮箱待运营提供后在此给出）。

  • 工单／故障申报

    统一走工单系统流程提交（入口地址待运营提供后在此给出）；平台侧无独立工单系统——如实占位，不放假链接。

  • 技术问题自查

    多数调用问题不用等人：错误响应自带追踪号（X-Trace-Id），先按下方三步引导自查，查不出再走工单并附上追踪号。

联系人电话/邮箱与 OA 工单入口为占位说明——真实信息由运营提供后回填，页面结构已就绪

查不到数怎么办（三步）

  1. 先看平台状态

    打开运行视图：服务可用/同步状态异常会直接显示——平台侧在修就不用报障。

  2. 用追踪号反查这次调用

    错误响应头 X-Trace-Id 里的追踪号，粘到我的日志里精确反查这次调用（含被网关拦下的）；错误含义到术语表对照。

  3. 联系值班

    前两步没解决：走 OA 工单找值班（申报时附追踪号和现象截图），按上方响应时限跟进。

值班说明

  • 告警自动触发

    服务异常（不可用/同步失败）会自动触发告警到值班——多数情况值班先于你知晓，报障时附追踪号可加速定位。

  • 响应窗口

    平台侧故障按告警级别响应（P0 级即时）；字段口径、授权范围等咨询按工作时段回复。

  • 报障带三样

    追踪号（X-Trace-Id）＋调用时间＋现象截图——三样齐了工单一次到位。

值班通道接法：告警通道待运营接线（M1 判据＝告警事件落盘可查）；当前以 OA 工单为准
